03. Loop Methods

Understands the use case for Nodemon and its limitation to development.

Nodemon er tænkt specifikt til udvikling. Den gør det dejligt nemt og hurtigt at teste ting i sin app, man slipper for manuelt at skulle genstarte sin server hele tiden, fordi nodemon gør det automatisk, alt efter hvad du har sagt den skal holde øje med.
Den skal ikke bruges i produktion da automatisk genstart på den måde kunne skabe uforudsete problemer

Can use loop methods (+map, +filter, %reduce). Can choose the right one at the appropriate time:

Map når du gerne vil kalde en funktion på hvert element, og få et nyt array med præcis lige så mange elementer, som elementer i det originale array. 


const numbers = [65, 44, 12, 4];
const newArr = numbers.map(myFunction)

function myFunction(num) {
  return num * 10;
}
// newArr = [650, 440, 120, 40]

Filter når du gerne vil have et nyt array fyldt af elementer fra det originale array, som har bestået den test du har set 


  const numbers = [65, 44, 12, 4]
  const newArr = numbers.filter((num) => return num >= 40)
  // newArr = [65, 44]

Reduce når du gerne vil bruge alt i arrayet til at få en enkelt værdi det kunne f.eks. være summen af alle tallene i et array, eller gennemsnit. 


  const numbers = [65, 44, 12, 4]
  const numbersTotalSum = numbers.reduce((accumulator, currentValue) => accumulator + currentValue, initialValue)
  // numbersTotalSum = 125

Understands why a functional approach to loops is to be preferred and how to implement it without side effects.

Den funktionelle måde at gøre det på, betyder at vi gør det deklarativt, at vi beskriver hvad vi gerne vil have og undgår at skrive løkker selv, så vi ikke lige pludselig har et while loop uden exit condition i prod.
Det er også mere læsbart for mennesker, man kan godt gennemskue hvad .filter gør f.eks. 


  const numbers = [65, 44, 12, 4]
  // Imperativt: du styrer løkken helt selv, hvor lang tid den skal køre, hvornår den stopper osv.
const doubled = [];
for (let i = 0; i < numbers.length; i++) {
  doubled.push(numbers[i] * 2);
}

// Funktionelt: du beskriver bare den ændring du gerne vil have
const doubled = numbers.map((num) => num * 2);

Man undgår side effects ved at sikre sig at sine loops ikke ændrer noget uden for sig selv. Det kunne f.eks. være som mit imperative loop deroppe, som ændrer på doubled der ligger uden for loopet.

Understand the dangers of XSS and how to prevent it in frontend (avoiding innnerHTML) and backend (sanitizing).

Vi fik f.eks. vist hvordan man kunne parse JavaScript i andres browser ved at man med vilje lavede faulty img tags, som på error så kørte simpelt JS, hvilket ikke er helt optimalt, ville nogle mene.
I frontend kan man vælge f.eks. at burge textContent i stedet for, men den helt smarte er at bruge escapeHTML, som i mit projekt f.eks. 


  export function sanitizeXSS(string) {
    return string
        .replaceAll('&', '&')
        .replaceAll('<', '<')
        .replaceAll('>', '>')
        .replaceAll('"', '"')
        .replaceAll("'", ''')
        .replaceAll('`', '`')
        .replaceAll('/', '/');
}
